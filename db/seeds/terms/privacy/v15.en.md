## 1. General Provisions

SIGLENS is a web service that provides analysis of US stocks, Korean stocks and crypto, and the conversational AI service SIGLENS AI (ai.siglens.io). The operator has designed the Service so that non-members can use all core features without restriction, and membership registration is optional. Members receive additional tier-based benefits, and in that process the minimum amount of identifiable information is collected.

This Privacy Policy applies to the web service (hereinafter the "Service") provided by the operator, and explains the information collected from non-members and members respectively and how it is processed.

## 2. Items of Personal Information Collected and Collection Methods

For **non-members**, the operator does not directly collect personal information such as name, email address, or phone number for the purpose of identifying users (the email address of a user who directly subscribes to alert emails is covered by the alert email item below). However, the following information is automatically generated and collected for service operation and security purposes.

- Access logs: IP address, requested URL, HTTP status code, User-Agent, access date and time
- User environment settings stored in cookies and local storage (chart settings, selected technical indicators, etc.)
- If a user voluntarily uses the error report feature, the email address and inquiry content the user voluntarily provides (also forwarded to the operator by notification email as soon as it is received)
- AI question rate limiting: the IP address is converted into a SHA-256 hash in a form from which the original IP cannot be recovered, and is stored. It is automatically deleted after 24 hours and is not combined with other personal information.
- Non-member identification cookie (`siglens_guest`): a signed random identifier (UUID). It is not combined with a name, email address or the like, and is used only to limit how many AI analyses can be generated, to decide the daily free full view, and to limit how many questions a non-member can ask SIGLENS AI (ai.siglens.io). AI analysis generations are counted per identifier and per IP address hash and stored on the server for up to 1 day, then deleted automatically.
- Daily free full view record: to decide whether a visitor is eligible for that day's free full view, the server records three items: (1) the identifier above, stored as is (not hashed), (2) a hash (HMAC-SHA-256) made by combining the IP address and the date with a secret key, and (3) the codes of the symbols shown in full that day. The original IP address is not stored. The record is deleted automatically at 00:00 KST the next day and is not combined with other personal information.
- Access statistics (visitor count aggregation): a pseudonymized identifier created by combining the IP address and User-Agent and converting them into a SHA-256 hash, together with the access date, the User-Agent, the country code of the access, which of our sites was visited (siglens.io or ai.siglens.io), the path of the visited page (excluding the query string, and for shared link pages and SIGLENS AI conversation pages with the identifier part of the address removed), the source of the first visit converted into a service-level classification value chosen from a fixed list (for example ChatGPT, Google, Naver Finance, advertising, email, shared link; for statistics these values are grouped into the categories AI answer services, search engines, social media, blogs and communities, securities portals, advertising, email, shared links, and other external sites), and range values describing the visit history, is stored. The source of the first visit is derived by converting the domain of the site visited just before arriving, the campaign tags (utm_source, utm_medium), whether the address contains an advertising click identifier (such as gclid), and whether the visited page is a shared link page into fixed category values; the original domain, address, search terms, original campaign tags, and the value of the advertising click identifier are not stored. The visit history range values are the number of days since the first visit from this browser, the number of days since the previous visit, and the number of days visited, each converted into one of six ranges, together with whether this visit is the first return within one of these periods: the day after the first visit, 7 to 13 days after it, or 30 to 36 days after it. They are calculated inside the browser from a record of visit dates kept in browser local storage, and the exact dates and counts are not sent to the server (see Section 7). The original IP address is not stored, and it is not combined with other personal information. It is used only to determine the scale of service users (daily and monthly active users), the scale of users by traffic source, and the return visit rate, and to identify automated bot traffic.
- Service usage behavior: impressions and clicks of sign-up prompts, impressions and clicks of the daily free full view notice, clicks on prompts for member-only features, the path by which a sign-up was completed, the creation and opening of analysis share links (only the kind of analysis shared is recorded, not the symbol or the link address), and whether a member returned (visit date). Recorded under the same pseudonymized identifier as the access statistics; for logged-in members it is stored together with the member identifier. Free-form input such as search terms or URLs is not recorded.
- Symbol view counts: after a symbol page is opened and the screen is first operated (mouse, touch, key input, etc.), only a count per symbol code and date (KST) is added on the server. When browser storage is available, a symbol is added at most once a day in the same browser; when it is not, a symbol can be added every time its page is viewed. The IP address, User-Agent, pseudonymized identifier, and member identifier are not stored, and the count is not linked to any visitor (the User-Agent of the request is checked on the spot to filter out automated requests but is not stored). It is used only to decide the list of popular symbols.
- Advertising performance measurement (Google Ads conversion tracking): the Google tag included in the service's pages sends Google advertising cookie identifiers, the ad click identifier (such as gclid) when the user arrived by clicking an ad, the IP address, the User-Agent, the address of the visited page, and the type and time of conversion actions (completing sign-up, sending a question to SIGLENS AI, selecting a stock in search) to Google. Information that directly identifies the user, such as name or email, is not sent, and this data is not used for personalized advertising (remarketing).
- Traffic and page performance measurement (Cloudflare Web Analytics): the service pages of siglens.io include a measurement script from Cloudflare (it is not loaded on ai.siglens.io or on the advertising landing pages). The script sends the address of the visited page and browser information to Cloudflare to measure the number of visits and page performance. What Cloudflare stores and for how long follows Cloudflare's policies.
- If the feedback features are used (the rating window shown after the service has been used several times, thumbs up/down on AI responses), the rating (1 to 5), comment, thumbs up/down and selected reasons the user provides, and the original AI response that was rated (the analysis result, or the conversation up to the SIGLENS AI answer, consisting of questions, answers, and the names and summaries of the tools used for the answer) are stored together with the context listed below. If the original exceeds 256 KB, long text is truncated before storing, and if it still cannot be brought under that size, the original is not stored. For non-members, feedback is not stored together with the non-member identification cookie or the IP address.
- Feedback context (all feedback): where it was given (siglens.io or SIGLENS AI), the page path viewed (without the query string), display language, and submission time
- Feedback context (ratings): what triggered the rating window
- Feedback context (AI response ratings on analyses): analysis type, symbol, timeframe, AI model used, whether reasoning mode was used, analysis time, generation time, options expiration date, analysis scope or category (only those that apply to the analysis), and whether the easy view or the original view was being shown
- Feedback context (ratings of SIGLENS AI answers): position in the conversation, whether the user was a non-member, and for members the identifiers of the conversation and the answer
- Feedback and inquiry submission rate limiting: the IP address is converted into a hash in a form from which the original IP cannot be recovered, and is stored. It is automatically deleted 1 hour after being stored and is not combined with other personal information.
- If the SIGLENS AI (ai.siglens.io) chat feature is used: the messages entered, attached images (up to 4 per message) and market data retrieved to generate the answer. Attached images are stripped of embedded metadata such as location and downscaled before they are sent. This information is sent to DeepSeek (China) to generate the answer, or to Google's Gemini (United States) when DeepSeek cannot respond. Non-member conversations and attached images are not stored on the server.

If a user chooses to register as a **member**, the following information is additionally collected to identify and authenticate the member.

- Email address (required)
- If email verification is requested for sign-up: the verification code is kept, only as a hash, together with the email address for 30 minutes, and the mark that verification is complete (including a hash of a random value that identifies the browser that verified) is kept for up to 30 minutes until sign-up is finished. To limit verification email requests and code entries, a hash of the email address and a hash of the connecting IP address are kept for up to 24 hours.
- Password: the plaintext password is not stored; it is retained only in bcrypt hash form.
- Display name (optional)
- If social login is used, the OAuth provider's account identifier (provider account id) and profile image URL (optional)
- Authentication session token: stored in an HttpOnly cookie and used by the server to verify session expiration.
- Membership tier: one of free, member, or pro
- If the SIGLENS AI (ai.siglens.io) chat feature is used: the messages entered, attached images (up to 4 per message), market data retrieved to generate the answer, and any portfolio holdings the member has registered (symbols, quantities, average prices). Attached images are stripped of embedded metadata such as location and downscaled before they are stored and sent. This information is sent to DeepSeek (China) to generate the answer, or to Google's Gemini (United States) when DeepSeek cannot respond. Conversations, including attached images, are stored on the member's account and can be deleted by the member from the conversation list.
- If the member subscribes to the email report: whether to receive it, the days and time of delivery, time zone, email language, the time consent to receive it was given, the screen on which consent was given (the signup screen, the consent screen of a social login signup, or the email report settings screen), and delivery records (delivery date, the holdings and watchlist stocks included in the report, delivery result). Only the stock names (tickers) of the holdings the member registered in the portfolio and of the watchlist are used in the report; quantity and average purchase price are not used. Holdings come first, then watchlist items from most recently added, up to 20 stocks in total. When the member removes a stock from the report on the email report page, its symbol and the time it was removed are stored on the server, and that stock is skipped when the report is assembled (removed stocks are stored even if the member has not subscribed to the email report). If the member chooses to receive the email report on the signup screen or on the consent screen of a social login signup (this is optional and not selected by default), delivery is set to every Monday at 8 AM, in the time zone of the browser used at that time (Seoul if it cannot be determined), in the language of the signup screen, and can be changed on the email report settings page.
- If an alert email subscription is made (by members and non-members alike): the email address, the items to receive (symbol codes, signal types, the Fear & Greed market) and the time each item was added, the email language, the time of the first subscription and the screen on which it was made (one of the stock screen, the Fear & Greed screen, the signal stocks screen, or the alert email settings screen), whether a member chose to also receive their holdings and watchlist, and the delivery records (delivery date, items included in the email, delivery result). A subscription is stored only after the address is confirmed by entering a verification code sent by email. The verification code is kept only as a hash for 30 minutes, and to limit verification email requests, code entries and item additions, a hash of the email address and a hash of the connecting IP address are kept for at most 1 hour. If a member with the same email address exists, the subscription is linked to that member's account.
- Watchlist: the symbols a member saves, their display names, and the time each was added. Stored on the server linked to the member's account, and used to show the watchlist (the header watchlist button, the home page and the Watchlist page) and the ☆ state on the stock page, and, if the member has turned on the email report, they are included as stocks covered by the report. A watchlist saved in the browser before logging in is sent to the server once at login and added to the account (see Section 7).
- AI provider API keys registered by the member (BYOK): if the member registers one, the provider (one of Anthropic, Google, OpenAI and DeepSeek), the API key encrypted with AES-256-GCM under an encryption key held by the server, and the registration and update times. The API key is stored only in encrypted form and is never stored in plain text. The server decrypts it only when it calls the provider for a feature the member has requested. After registration it is not shown on screen again, and only whether it is registered is displayed. Only one key is stored per provider, and registering again overwrites the existing key.
- SIGLENS API keys: if a member issues a SIGLENS API key, the key name chosen by the member, the leading part of the key shown in the key list (display prefix), the SHA-256 hash of the key, the issue time, the last-used time, and the revocation time. The raw key is not stored and is shown only once, when it is issued. The last-used time is updated at most once per minute.
- Temporary records for processing SIGLENS API requests (Redis): when a request arrives with an API key, the key identifier, key name, display prefix, member identifier and member tier are stored for 60 seconds, keyed by the key hash, as the authentication result; when a key is revoked or the member withdraws, the key hash is stored for 120 seconds as a revocation marker. To prevent abuse, the number of requests per member identifier is also counted and stored per minute and per day.
- SIGLENS API default AI model setting: the default AI model the member has chosen for API requests (optional). It is stored on the server linked to the member's account.
- If the feedback features are used, the same feedback content as in the non-member items above is stored linked to the member account. When an answer from SIGLENS AI (ai.siglens.io) is rated, it is also linked to the rated conversation.

Collection method: non-member information is automatically collected when a user accesses and uses the Service, and member information is either entered directly by the member during the sign-up, login, or social login process, or received from the OAuth provider based on the member's own consent.

## 3. Purpose of Collecting and Using Personal Information

The operator uses the collected information only for the following purposes, and does not use it for any other purpose.

- Providing and operating the Service: retrieving chart data, providing AI technical analysis results
- Member identification and authentication, and providing features according to membership tier
- Sending the periodic email report the member subscribed to, and preventing duplicate deliveries
- Sending the alert emails requested, limiting delivery to one email a day and preventing repeated delivery of the same news, and preventing abuse of verification emails
- Improving service quality: analyzing access statistics (including the scale of users by traffic source and the return visit rate), tracking and reproducing errors
- Service improvement: measuring whether sign-up prompts, member-only feature prompts and the daily free full view notice actually lead to sign-ups and return visits, and whether shared links of analyses lead to new visits
- Measuring advertising performance: counting whether users who arrived through an ad went on to sign up, ask SIGLENS AI a question, or search for a stock (not used for personalized advertising)
- Security and prevention of fraudulent use: detecting and blocking abnormal access, preventing account theft
- Limiting how many AI analyses a non-member can generate and deciding the daily free full view (including preventing abuse)
- Calling the provider for AI features the member requests, using the AI provider API key the member registered (not used for any other purpose)
- Providing the SIGLENS API: authenticating members who make requests with an API key they issued, preventing abuse through request rate limits, showing members their own list of API keys (key name, display prefix, issue time, last-used time), and applying the default AI model setting
- Improving service quality: evaluating and improving the quality of AI responses based on feedback (ratings, comments, ratings of AI responses), and sending emails that notify the operator of received inquiries and feedback
- Responding to user inquiries and handling error reports

## 4. Retention and Use Period of Personal Information

The operator retains the collected information for the following periods and then destroys it without delay.

- Access logs: up to 3 months from the date of collection (for service stability and incident response purposes)
- Access statistics (visitor count aggregation): up to 400 days from the date of collection (for the purpose of comparing user trends against the same month of the previous year)
- Service usage behavior (sign-up prompts, member-only feature prompts, daily free full view notice, sign-up path, creation and opening of share links, member return visits): up to 400 days from the date of collection. When a member withdraws, records linked to the member identifier are deleted immediately and the member link on access-statistics rows is removed.
- Symbol view counts (daily view count per symbol code): up to 90 days from the date of collection
- Email addresses and inquiry content related to error reports: 1 year after processing is completed
- Feedback (ratings, comments, thumbs up/down and reasons, the original AI response that was rated and its context): automatically deleted 1 year after collection. A member's feedback is destroyed immediately when the member withdraws, and when a member deletes a SIGLENS AI conversation, the feedback linked to that conversation is also destroyed immediately
- IP address hash for feedback and inquiry submission rate limiting: automatically deleted 1 hour after being stored
- Cookies and local storage: until the user directly deletes them through browser settings
- Non-member identification cookie (`siglens_guest`): up to 1 year in the browser. AI analysis generation and SIGLENS AI question counters keyed to this identifier: up to 1 day on the server
- Daily free full view record (identifier, IP address hash, codes of symbols shown in full): deleted automatically at 00:00 KST the next day
- Google advertising conversion cookies (starting with `_gcl_`): up to 90 days in the browser. The retention of conversion records processed by Google follows Google's policies.
- Temporary sign-up conversion cookie (`siglens_signup_conversion`): up to 10 minutes after it is issued
- Temporary cookie for sign-up path measurement (`siglens_funnel_signup`): up to 10 minutes after issuance
- Sign-up verification confirmation cookie (`siglens_signup_verify`): up to 30 minutes after issuance
- Member information (email, password hash, display name, OAuth connection information, tier): destroyed without delay upon membership withdrawal. However, if retention is required under applicable law, it is retained for the period required by that law.
- Authentication session: up to 30 days from the date of issuance, or immediately discarded upon logout or session expiration
- Sign-up email verification data (verification code hash, verification-complete mark and a hash of a random value that identifies the browser that verified): the code is automatically deleted after 30 minutes and the complete mark after up to 30 minutes until sign-up is finished. Hash of the email address and hash of the IP address used to limit requests and entries: automatically deleted up to 24 hours after being stored
- SIGLENS AI conversation history (messages, attached images, conversation titles, retrieved market data, portfolio holdings): retained until the member deletes the conversation from the conversation list, and destroyed immediately upon deletion. All conversation history is destroyed immediately upon account withdrawal, and no other automatic retention period applies
- Email report settings (whether to receive it, days, time, time zone, email language, time of consent, screen on which consent was given): destroyed immediately upon membership withdrawal. If the member unsubscribes, the settings remain in an "off" state and no further emails are sent.
- Email report delivery records (delivery date, included stocks (holdings and watchlist), delivery result): automatically deleted 90 days after the delivery date, and destroyed immediately upon membership withdrawal
- Alert email subscription information: deleted immediately when the subscriber unsubscribes or removes every item to receive (kept until a member turns off receiving their holdings and watchlist together). Destroyed immediately upon membership withdrawal (including alerts subscribed to as a non-member with the same email address)
- Alert email delivery records (delivery date, items included, delivery result): automatically deleted 90 days after the delivery date, and destroyed immediately upon unsubscribing or membership withdrawal
- Stocks removed from the report (symbol, time removed): kept until the member adds them back or clears the record, and destroyed immediately upon membership withdrawal
- Watchlist (symbols, display names, time added): retained until the member removes it from the list, and destroyed immediately upon membership withdrawal
- AI provider API keys registered by the member (encrypted key, provider, registration and update times): retained until the member deletes them on the account page, and destroyed immediately upon deletion. Destroyed immediately upon member withdrawal
- SIGLENS API key information (key name, display prefix, key hash, issue, last-used and revocation times): destroyed immediately upon member withdrawal. A key revoked by the member is retained with its revocation time recorded (it is not shown on the account page); because there is no separate automatic deletion, it is retained until the member withdraws
- SIGLENS API authentication result records: automatically deleted 60 seconds after being stored. Revocation markers are automatically deleted 120 seconds after being stored. Request counters are automatically deleted 2 minutes (per-minute counters) or 25 hours (per-day counters) after they were last updated
- SIGLENS API default AI model setting: retained until the member changes or clears it, and destroyed immediately upon member withdrawal
- If the feedback features are used, the same feedback content as in the non-member items above is stored linked to the member account. When an answer from SIGLENS AI (ai.siglens.io) is rated, it is also linked to the rated conversation.

If retention is required under applicable law, the information is retained for the period prescribed by that law.

## 7. Cookies and Local Storage

For user convenience, the operator uses browser cookies and local storage. Cookies and local storage store service environment settings such as chart settings, selected technical indicators, and analysis panel status.

If a member is logged in, the operator additionally uses the following security cookie to identify the authentication session.

- **siglens_session**: the authentication session token. HttpOnly, SameSite=Lax, and in the production environment the Secure flag is applied; the maximum expiration period is 30 days. It cannot be accessed via JavaScript.
- **siglens_auth**: a hint cookie that indicates the login state. Its value is always `1` and it can be read by scripts (it is used to show a screen that matches the login state and is not used for authentication). It is set at login and deleted at logout or withdrawal, and its expiry equals that of the session cookie, up to 30 days.
- **siglens_oauth_state**: a temporary security cookie set when social login starts. It contains a signed random value, the login provider, and the address to return to after login, is HttpOnly, and is deleted after up to 5 minutes or as soon as login processing ends.
- **siglens_ai_sso_state** (`__Host-siglens_ai_sso_state` in the production environment): a temporary security cookie set by ai.siglens.io while the login state is passed between siglens.io and ai.siglens.io. It contains only a random verification value, is HttpOnly, and is deleted after up to 5 minutes or as soon as the transfer ends.
- **siglens_ai_sso_probed**: a cookie set by ai.siglens.io when the process above found no logged-in session on siglens.io, so that the same process is not repeated. Its value is `1`, it is HttpOnly, and it expires after 30 minutes.

## 8. User Rights and How to Exercise Them

Under the Personal Information Protection Act (개인정보 보호법), users have the right to request access, correction or deletion, and suspension of processing of their own personal information handled by the operator.

For non-members, because the collection of personally identifiable information is minimized, there may be no information subject to the exercise of this right if no separate personal information has been stored.

Members may withdraw their membership at any time after logging in, directly on the [Account Settings → Delete Account](/account/delete) page. Upon withdrawal, all member information (email, password hash, display name, OAuth connection information, tier) and all active sessions are immediately and permanently destroyed. However, if retention is required under applicable law, the information is retained only for the period required.

After logging in, members may revoke the SIGLENS API keys they issued at any time on the account page, after which the key can no longer be used to authenticate. Upon member withdrawal, the information on the keys they issued is also deleted, and those keys can no longer be used.

Even for members who signed up via social login (Google), the app access permission registered with the external provider account is automatically revoked upon withdrawal, and the OAuth connection information held by the operator is also destroyed at the same time.

Members can unsubscribe from the email report at any time, using the unsubscribe link at the bottom of the email, the unsubscribe button provided by their email app, or the [Email Report](/email-report) settings page after logging in. Once unsubscribed, no further emails are sent. Not choosing the email report at signup places no restriction on signing up or using the service.

Alert emails can be turned off at any time using the unsubscribe link at the bottom of the email, the unsubscribe button of the email app, the settings link in the email, or the [alert email settings](/email-report/alerts) screen after logging in. Turning them off immediately deletes the subscription information and delivery records.

Members who use the SIGLENS AI (ai.siglens.io) chat feature can delete individual conversations directly from the conversation list, and a deleted conversation is destroyed immediately.

If a user wishes to view or delete the inquiry content they provided through an error report, they may make the same request using the same contact information.
