R3 review of `feat/i18n-multilingual` (worktree `/Users/y0ngha/Project/siglens-i18n`). Round 2's nav-`<Link>` finding (see [[project-i18n-multilingual-r2]]) was fixed correctly and the fix was widened project-wide: `src/shared/ui/LocaleLink.tsx` ('use client', wraps `next/link`, prefixes string hrefs via `localePath(locale, href)`, passes external/anchor/object hrefs through) is now the **sole** entry point — verified live via `grep -rln "from 'next/link'" src` → only `LocaleLink.tsx` itself and its own guard test (`noRawNextLink.test.ts`) match; 52 files correctly import `LocaleLink as Link`. Locale source is a new plain `LocaleContext` (`src/shared/i18n/LocaleContext.tsx`) mounted in `[locale]/layout.tsx` above `NextIntlClientProvider` — defaults gracefully with no provider (doesn't throw), a deliberate choice over `useLocale()`/`usePathname()` to avoid breaking ~70 partial-mock tests (same rationale as R1/R2). `useLocalePath()` hook correctly threaded into `useAutocomplete` (push+prefetch), `OnboardingContent`, `useTimeframeChange`'s `router.replace`. The 4 auth-gated pages (`account`, `account/delete`, `onboarding`, `portfolio`) correctly build locale-prefixed `redirect()` targets via `localePath(locale, '/login')?next=encodeURIComponent(localePath(locale, ...))`. `router.push`/`router.replace` call sites that reuse the current `usePathname()` (`useQueryParamState`, `useSectorSignalState`, `useBacktestFilter`) correctly left untouched — confirmed those all read raw `next/navigation` `usePathname()` (locale-prefixed), not the intl-wrapped one.

**New required finding 1 — `window.history.replaceState` locale-loss, same file the round's own fix touched.**
`src/views/symbol/hooks/useTimeframeChange.ts:101-105`. The file correctly wraps its `router.replace()` call (line 72-77) with `toLocalePath(...)`, but a *second* navigation path in the same effect — the free-tier intraday-deeplink canonicalization — calls `window.history.replaceState(null, '', \`/${symbol}?tf=${DEFAULT_TIMEFRAME}\`)` with a raw unprefixed template literal, bypassing `toLocalePath` entirely. Fires whenever a free-tier user loads `/en/AAPL?tf=1Hour` (or similar intraday deep link) — the effect silently rewrites the URL to `/AAPL?tf=1Day`, dropping the `/en` prefix client-side with no full navigation (so it's invisible to network/router-level checks). Root cause: `window.history` is a raw browser API, not `next/navigation`'s router, so it wasn't caught by the `router.push`/`router.replace` audit that found the other 3 sites.

**New required finding 2 — systemic, unaddressed: Server Action `redirect()` calls hardcode unprefixed paths.**
This is the exact same bug class the whole R1→R3 effort has been fixing for `<Link>`/`router.push`, but for the **Server Action redirect surface**, entirely untouched by any round including R3, and not mentioned in the design doc at all (grepped for "서버 액션"/"redirect" — zero hits in the relevant section). Confirmed via `grep -rn "redirect(" src` (excluding proxy.ts/route handlers, which build full `NextResponse.redirect(new URL(...))` and are fine):
- `src/features/auth-logout/actions/logoutAction.ts:30,35` — `redirect('/')`. Reachable from every authenticated page via `useLogout()` (header sign-out button) — clicking logout from `/en/...` lands on ko `/`.
- `src/features/account-delete/actions/deleteAccountAction.ts:77` — `redirect('/?account_deleted=1')`.
- `src/features/auth-oauth/actions/cancelOAuthSignupAction.ts:21,27` — `redirect('/login')`.
- `src/features/auth-password-reset/actions/confirmPasswordResetAction.ts:61` — `redirect('/login?password_reset=1')`.
- `src/entities/api-key/actions/{deleteApiKeyAction.ts:17, saveApiKeyAction.ts:66}` — both `redirect('/login?next=/account')` (session-expired-mid-action on the /account page, which itself is correctly locale-prefixed at the page-guard level — inconsistent).
- `src/entities/auth/lib/errorMessages.ts:10-15` (`OAUTH_ERROR_REDIRECT` — `consentInvalid`/`consentExpired`/`serviceUnavailable`/`emailConflict`, all `/login?error=...`), consumed by 9 `redirect()` call sites in `src/features/auth-oauth-consent/actions/finalizeOAuthSignupAction.ts`.
- Lower-priority edge: `sanitizeNextPath`'s `DEFAULT_REDIRECT_PATH = '/'` fallback (`src/shared/lib/auth/redirect.ts`) — only fires when `next` is missing/invalid, but still locale-oblivious.
No `localeRedirect`/`redirectWithLocale` helper exists anywhere (grepped, zero hits) — confirms this wasn't deliberately deferred, just missed. Fix belongs in one shared place (root-cause, not per-caller patches) since Server Actions can't call the client-only `useLocalePath()` hook — needs an explicit locale channel into the action (hidden form field, or referer/header derivation at the `'use server'` boundary).

**Verified NOT a bug (checked, no finding):** `global-error.tsx` imports `LocaleLink` but has no `LocaleProvider` ancestor (it replaces the root layout on a root-level crash) — falls back to default locale `ko`, consistent with its already-hardcoded `lang="ko"`; acceptable degradation given there's no reliable locale signal at that failure point. Minor stale-comment nit only (comment claims "no shared/ui imports" but now imports `@/shared/ui/LocaleLink`) — too trivial to flag as required. JSON-LD locale-invariance deferral (R2's minor finding) re-verified against the design doc §7.1 — factually accurate (`STATIC_INDEXABLE_LOCALES`/`SYMBOL_INDEXABLE_LOCALES` ko-only today, zero current SEO impact, explicit Phase-2-blocker language with a concrete file list) — did not re-litigate per task instructions.

**Verification technique reused:** `grep -rln "from 'next/link'" src` to independently re-run the guard test's own check rather than trusting the test exists; `grep -rn "redirect(" src` swept the *entire* redirect surface (not just files in the round's `modified_files` list) — this is what caught finding 2, since the task prompt explicitly asked to look for "remaining locale-losing navigation paths... server actions, form actions" beyond the modified-files scope.
