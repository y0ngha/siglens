메모리·주석·이전 실측을 전부 무시하고 GSC·Cloudflare·라이브 프로브·코드를 처음부터 다시 봤다.
이 문서는 **무엇이 사실로 확인됐는지**, **무엇이 원인이 아닌지**, 그리고 **회복을 위해 무엇을
어떤 순서로 하는지**를 기록한다. 숫자는 전부 2026-09-11 GSC(`sc-domain:siglens.io`) 실측이다.

## 3. 원인 판정 — 사이트 단위 품질 강등

Google이 색인해 둔 사이트의 모습(2026-06 시점):

- 색인 **50,873** URL. 그중 sitemap이 의도한 것은 **3,596**. 나머지 ~47K는 롱테일 티커 × 9탭.
- 롱테일 페이지의 본문은 "`XXX은 최근 종가 $… 기준으로 직전 봉 대비 …% 하락했습니다. RSI …`" 템플릿
  한 문단이 전부다. `site:siglens.io` 결과의 스니펫이 전부 이 문장이다 — Google이 본 이 사이트의 "콘텐츠"가 그것이다.
- YMYL(투자) 도메인에서 AI 생성 문장을 수만 페이지에 뿌리고, 운영 주체·방법론·저자 정보가 없다.

즉 7월 core update가 이 사이트를 **"숫자만 바뀌는 템플릿 페이지 수만 개짜리 프로그래매틱 금융 사이트"**로
분류했고, 6월에 잠깐 잡혔던 롱테일 순위가 통째로 회수됐다. 기술적 차단이 아니라 품질 판정이다.

## 4. 지금 상태 — 강등 이후 두 달 동안 코퍼스가 줄지 않았다

07-08에 롱테일을 `noindex`로 게이트했지만(`evaluateSymbolIndexability`), Google 쪽 색인 수는 그대로다:

| GSC 페이지 보고서 (09-04 기준) | 수 | 해석 |
|---|---|---|
| 색인 생성됨 | **50,873** | 07월 이후 거의 불변. noindex를 아직 못 본 URL이 ~47K |
| NOINDEX로 제외 | 14,743 | 두 달간 재크롤로 noindex를 확인한 양 |
| **발견됨 – 현재 색인 생성되지 않음** | **45,635** | 08-07~08-16 removal sitemap 제출 직후 0 → 45K로 급증. 전부 **한 번도 색인된 적 없는** 롱테일 |
| 크롤링됨 – 색인 생성되지 않음 | 12,324 | 롱테일 |
| 크롤 예산 | ~3.2K 요청/일, HTML은 28% | HTML 크롤 샘플 10/10이 롱테일 noindex 페이지 |

핵심: `sitemap-removal-{chart,news,overall}.xml`(총 82K URL)은 **색인된 적 없는 45K URL을 발견 큐에
밀어 넣었고**, 정작 색인돼 있는 47K의 재크롤은 앞당기지 못했다. 하루 ~900건의 HTML 크롤이 이 큐에
쓰이고 있다.

부수 관측:
- 크롤의 58%가 "다른 파일 형식"(text/x-component = RSC 페이로드), 69%가 "페이지 리소스 로드" — 렌더 한 번에
  다른 심볼 페이지의 RSC를 끌어온다. 코드상 `prefetch={false}`는 v0.52.5부터 대부분 적용돼 있어 90일 통계의
  잔상일 가능성이 크지만, 09-09~10 샘플에도 남아 있다. Cloudflare Speed Brain(speculation rules)이 켜져 있다.
- `/{ticker}/position` 402 URL이 PR #791(2026-09)로 sitemap에 추가됐다. SSR 고유 텍스트 868~1,222자
  템플릿(형제 탭은 2~8천 자), 16개월 노출 0건.

## 5. 전략 — 세 축, 우선순위 순

회복은 "Google이 이 사이트를 다시 평가할 때 색인 코퍼스가 대부분 유용한 페이지여야 한다"로 귀결된다.
core update 강등은 다음 재평가(연속 롤아웃 포함) 때 풀리며, **주 단위가 아니라 월 단위**다.

### A. 색인 코퍼스를 3,200개 안팎의 "산문이 있는 페이지"로 좁힌다 (최우선)

| # | 조치 | 어디서 | 상태 |
|---|---|---|---|
| A1 | `sitemap-removal-{chart,news,overall}.xml` GSC 제출 **삭제** | GSC › Sitemaps | 대시보드 (사용자 확인 후) |
| A2 | `/{ticker}/position` 항상 noindex + sitemap 제외 (#791 되돌림) | 코드 | **이 PR** |
| A3 | 인기 종목이라도 스냅샷 산문이 없는 탭은 noindex — 이미 `degraded` 게이트가 담당 | 코드 | 유지 |
| A4 | 롱테일 noindex 유지. 6월 트래픽이 거기서 났더라도 되돌리지 않는다 — 그게 강등 사유다 | 코드 | 유지 |

A1의 근거: removal sitemap의 목적(noindex 재크롤 유도)은 두 달간 색인 수를 1건도 줄이지 못했고, 대신 45K의
미색인 URL 발견을 만들었다. 삭제하면 HTML 크롤 예산이 사이트맵·내부 링크로 도달하는 URL, 즉 색인돼 있는 것들의
refresh 크롤로 돌아간다. 라우트는 남겨 둔다(재제출이 필요하면 좁혀서).

### B. 남는 페이지의 신뢰 신호 (YMYL)

## 6. 이 PR이 하는 것 / 하지 않는 것

**한다**: A2. `[symbol]/position` generateMetadata를 항상 `noindex, follow`로, `buildPopularEntries`·
`buildCryptoPopularEntries`에서 position 엔트리 제거(−402 URL, sitemap-popular 3,433 → 3,031, crypto 145 → 116).

## 7. 측정 — 무엇이 움직여야 "먹혔다"인가

| 지표 | 지금 | 기대 (4~8주) | 어디서 |
|---|---|---|---|
| 색인 생성됨 | 50,873 | **감소 시작** (A1 뒤 refresh 크롤이 noindex를 보기 시작) | GSC › 페이지 |
| 발견됨-미색인 | 45,635 | 정체 또는 감소 (신규 발견 0) | GSC › 페이지 |
| HTML 크롤 샘플 | 10/10 롱테일 | 인기 종목 비율 상승 | GSC › 크롤링 통계 › HTML |
| 노출/일 | 12~44 | 다음 core update 전까지는 **변화 없어도 정상** | GSC › 실적 |

노출이 오르지 않는 것 자체는 실패 신호가 아니다. 색인 수가 두 달 뒤에도 50K대면 A1이 안 먹힌 것이고,
그때는 removal sitemap을 "실제로 색인된 URL"로 좁혀 재제출한다(GSC 실적 16개월 페이지 목록 + `site:` 샘플).
